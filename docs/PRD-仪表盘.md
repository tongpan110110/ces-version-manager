# 仪表盘 PRD

> **对话恢复提示**：如果你是新对话，请先阅读本文档以及 `docs/` 目录下的其他 PRD 文档，了解之前的设计讨论。阅读完成后，可以继续设计下一个页面或修改现有设计。

---

## 一、页面定位

仪表盘是系统入口页面，提供**版本发布全局视图**，让开发、测试、SRE、版本经理快速了解版本的当前情况和生命周期。

---

## 二、核心设计原则

1. **以版本线为主线**：通过 Tab 切换不同版本线，所有模块联动
2. **突出当前重点**：当前升级中的版本是核心焦点
3. **简洁直观**：仪表盘只展示概览信息，详情点击进入
4. **术语通俗化**：不用"对齐率"，改用"升级进度"

---

## 四、模块说明

### 4.1 版本线 Tab

- **功能**：切换当前版本线
- **数据来源**：SystemConfig 中的 `active_version_lines`
- **交互**：切换后，下面所有模块数据联动更新

---

### 4.2 当前升级中

- **功能**：展示当前版本线的目标版本及升级进度
- **数据来源**：
  - 目标版本：SystemConfig 中的 `baseline_{versionLine}` 对应的 Plan
  - 升级进度：分别统计后端和前端的升级情况

- **卡片内容**：
  - 版本号
  - 版本类型标签（Release/Patch）
  - 版本描述
  - 查看详情入口
  - 升级进度（后端和前端分开显示）
    - 后端：已升级局点数 / 总局点数 + 进度条 + 百分比
    - 前端：已升级局点数 / 总局点数 + 进度条 + 百分比

- **升级顺序**：后端先升级，前端后升级

- **特殊状态**：
  - 后端和前端都 100%：显示"已完成"
  - 无目标版本：显示"暂无升级中的版本"

---

### 4.3 补丁版本

- **功能**：展示当前版本线进行中的补丁
- **数据来源**：当前版本线内 type=Patch 且状态为 开发中/测试中/升级中 的计划
- **排序**：升级中 > 测试中 > 开发中，同状态按更新时间倒序
- **显示数量**：Top 3
- **显示规则**：无进行中补丁时，整个模块隐藏

- **卡片内容**：
  - 版本号
  - 版本类型标签（Patch）
  - 状态标签
  - 版本描述
  - 查看入口

- **底部**：
  - 显示"共 X 个补丁"
  - 查看全部入口（跳转到发布计划列表，筛选 Patch）

---

### 4.4 版本进度

- **功能**：按状态分列展示排队中的版本
- **数据来源**：当前版本线内 type=Release 的计划（排除目标版本）
- **三列**：
  - 开发中（draft）
  - 测试中（testing）
  - 研发出包（released）
- **排序**：每列按创建时间倒序
- **显示数量**：每列 Top 3

- **卡片内容**：
  - 版本号
  - 版本类型标签（Release）
  - 版本描述
  - 查看入口

- **底部**：
  - 查看全部入口（跳转到发布计划列表）

## 五、版本状态定义

### 5.1 状态流转

```
draft → testing → released → upgrading → completed
开发中 → 测试中 → 研发出包 → 升级中 → 已完成
```

### 5.2 状态映射

| 数据库状态 | 页面显示 | 说明 |
|-----------|---------|------|
| draft | 开发中 | 研发正在开发 |
| testing | 测试中 | 测试正在验证 |
| released | 研发出包 | 测试通过，研发已出包，等待升级 |
| upgrading | 升级中 | 正在全网推广 |
| completed | 已完成 | 全网拉齐完成 |

### 5.3 删除的状态

- `ready`：删除，用 `released` 替代
- `deprecated`：删除，废弃版本直接删除记录

---

## 六、业务规则

### 6.1 升级串行规则

- 全网同一时间只有一个版本在升级
- 一个版本全网拉齐后，才升下一个版本
- 补丁版本可以在升级过程中紧急插入

### 6.2 目标版本规则

- 目标版本由版本经理在系统设置中手动配置
- 不自动切换
- 100% 拉齐后显示"已完成"，提醒更新目标版本

### 6.3 版本线规则

- 多版本线可并行存在（如 25.8.x 和 25.10.x）
- 每个版本线独立配置目标版本
- 开发和测试可以跨版本线并行，但升级是串行的

---

## 七、交互说明

### 7.1 点击行为

| 元素 | 点击行为 |
|-----|---------|
| 版本线 Tab | 切换版本线，所有模块联动 |
| 版本卡片 / 查看详情 | 跳转到发布计划详情页 |
| 查看全部（补丁） | 跳转到发布计划列表，筛选当前版本线 + Patch |
| 查看全部（版本进度） | 跳转到发布计划列表，筛选当前版本线 |

### 7.2 数据刷新

- 页面加载时获取数据
- 切换版本线 Tab 时重新获取对应数据

---

## 八、数据口径

| 指标 | 计算方式 |
|-----|---------|
| 后端升级进度 | 后端已升级到目标版本的局点数 / 本版本线局点总数 |
| 前端升级进度 | 前端已升级到目标版本的局点数 / 本版本线局点总数 |
| 补丁数量 | 当前版本线内 type=Patch 且状态为 开发中/测试中/升级中 的计划数 |
| 版本进度各列数量 | 当前版本线内对应状态的 Release 计划数（排除目标版本） |

**升级顺序规则**：后端先升级，前端后升级。不会出现"前端已升级，后端未升级"的情况。

## 九、与原设计的差异

| 原设计 | 新设计 | 原因 |
|-------|-------|------|
| 整体对齐率 | 删除 | 术语不直观，改用"升级进度" |
| 发布计划总数 | 删除 | 没有业务意义 |
| 全网对齐进度卡片 | 删除 | 与升级进度重复 |
| 待测试/待发布卡片 | 改为版本进度三列 | 更直观展示各版本状态 |
| 本版本线统计 | 删除 | 与升级进度重复 |
| 最近更新的版本计划 | 改为版本进度 | 按状态分类更有意义 |
| 关联需求/问题（仪表盘） | 删除 | 保持简洁，详情页查看 |
