# 局点版本页 PRD

---

## 一、页面定位

局点版本页是**全网局点升级状态的总览**，展示各局点当前版本及前后端升级情况，供版本经理和 SRE 了解升级进度。

---

## 二、核心设计原则

1. **一目了然**：快速看到哪些局点已升级、哪些待升级
2. **前后端分离**：清晰展示后端和前端的升级状态
3. **只做展示**：不提供编辑功能，数据通过代码维护
4. **支持筛选**：可按区域、版本线、状态筛选

## 四、模块说明

### 4.1 头部

- **标题**：局点版本

---

### 4.2 筛选区

一行三个筛选条件：

| 筛选项 | 类型 | 选项 |
|-------|------|------|
| 区域 | 下拉框 | 全部区域 / 国内 / 亚太/中东 / 非洲 / 拉美 |
| 版本线 | 下拉框 | 全部版本线 / 25.8.x / 25.10.x / ...（动态） |
| 状态 | 下拉框 | 全部状态 / 已升级 / 升级中 / 待升级 |

- **筛选逻辑**：实时生效
- **URL 参数**：筛选条件同步到 URL，支持从其他页面跳转
  - 示例：`/regions?version=25.8.2`

---

### 4.3 局点卡片

#### 按区域分组

局点按区域分组展示，每组显示区域名称和局点数量：

| 区域代码 | 显示名称 |
|---------|---------|
| domestic | 国内 |
| apac | 亚太/中东 |
| africa | 非洲 |
| latam | 拉美 |

#### 卡片内容

| 元素 | 说明 |
|-----|------|
| 局点名称 | 如"北京"、"上海" |
| 当前版本 | 该局点当前运行的版本号 |
| 后端状态 | ● 已升级 / ○ 待升级 |
| 前端状态 | ● 已升级 / ○ 待升级 |

#### 状态判断逻辑

| 状态 | 后端 | 前端 | 说明 |
|-----|------|------|------|
| 已升级 | ● | ● | 后端和前端都已升级到目标版本 |
| 升级中 | ● | ○ | 后端已升级，前端待升级 |
| 待升级 | ○ | ○ | 后端和前端都未升级 |

**注意**：不会出现「后端 ○ 前端 ●」的情况，因为后端一定先于前端升级。

---

## 五、升级规则

### 5.1 升级顺序

```
后端升级 → 前端升级 → 完成
```

- 后端先升级，前端后升级
- 不会出现前端先升级的情况

### 5.2 状态判断

- **已升级**：局点当前版本的后端和前端都已升级到目标版本
- **升级中**：后端已升级到目标版本，前端待升级
- **待升级**：后端和前端都未升级到目标版本

## 六、交互说明

### 6.1 点击行为

| 元素 | 点击行为 |
|-----|---------|
| 筛选下拉框 | 实时筛选局点列表 |

### 6.2 URL 参数

支持从其他页面跳转时带筛选参数：

| 参数 | 说明 | 示例 |
|-----|------|------|
| version | 版本号 | `25.8.2` |
| versionLine | 版本线 | `25.8` |
| area | 区域 | `domestic` |
| status | 状态 | `upgrading` |

示例：从发布计划详情页「查看局点详情」跳转
```
/regions?version=25.8.2
```

## 八、与现有设计的差异

| 原设计 | 新设计 | 原因 |
|-------|-------|------|
| 状态：已对齐/略落后/待升级/超前 | 已升级/升级中/待升级 | 简化，只关注升级状态 |
| BE/FE 缩写 | 后端/前端 | 更直观 |
| 有编辑功能 | 删除编辑功能 | 只做展示，数据通过代码维护 |
| 显示目标版本 | 删除 | 简化卡片，目标版本在筛选时已知 |
| 复杂的颜色图例 | 简化为 ● ○ | 更简洁 |

## 九、空状态

当筛选结果为空时显示：

```
暂无符合条件的局点
[清除筛选条件]
```
