# 发布计划详情页 PRD

---

## 一、页面定位

发布计划详情页是**版本计划的完整视图**，展示版本的基本信息、升级进度、关联内容和交付清单，供版本经理、开发、测试、SRE 查看和操作。

---

## 二、核心设计原则

1. **信息完整**：一页展示版本的所有关键信息
2. **状态清晰**：通过状态流程图直观展示当前进度
3. **操作简洁**：常用操作直接暴露，低频操作收纳
4. **SOP 友好**：交付清单可直接用于编写升级 SOP

## 四、模块说明

### 4.1 头部信息

- **返回按钮**：返回上一页（发布计划列表）
- **版本号**：大字体突出显示
- **版本线标签**：如 `[25.8.x]`
- **类型标签**：`[需求版]` 或 `[补丁版]`
- **状态标签**：当前状态（开发中/测试中/研发出包/升级中/已完成）
- **版本摘要**：简要描述版本内容
- **编辑按钮**：编辑版本基本信息（摘要、关联需求、关联缺陷）

---

### 4.2 状态流程图

- **功能**：可视化展示版本当前所处的状态
- **样式**：横向流程图，当前状态高亮（实心圆点）
- **状态流转**：
  ```
  ○ 开发中 ──→ ○ 测试中 ──→ ○ 研发出包 ──→ ○ 升级中 ──→ ○ 已完成
  ```

- **状态推进按钮**：
  - 仅在「开发中」「测试中」「研发出包」状态显示
  - 点击后推进到下一状态
  - 「升级中」→「已完成」由系统自动判断（全部局点升级完成后自动切换）

| 当前状态 | 按钮文案 | 点击后状态 |
|---------|---------|-----------|
| 开发中 | 提交测试 | 测试中 |
| 测试中 | 测试通过 | 研发出包 |
| 研发出包 | 开始升级 | 升级中 |
| 升级中 | （无按钮） | 自动切换 |
| 已完成 | （无按钮） | - |

---

### 4.3 升级进度

- **显示条件**：仅当状态为「升级中」时显示
- **内容**（后端和前端分开显示）：
  - 后端：已升级局点数 / 总局点数 + 进度条 + 百分比
  - 前端：已升级局点数 / 总局点数 + 进度条 + 百分比
- **升级顺序**：后端先升级，前端后升级
- **交互**：点击「查看局点详情」跳转到局点版本页面，筛选当前版本
  - 跳转地址：`/regions?version={版本号}`

- **特殊状态**：
  - 后端和前端都 100%：显示"已完成"，系统自动将状态切换为「已完成」

---

### 4.4 关联需求 / 关联缺陷

- **布局**：两列卡片
- **内容**：显示关联的需求 ID 和缺陷 ID 列表
- **空状态**：显示"暂无"
- **编辑**：通过头部「编辑」按钮修改

---

### 4.5 组件信息

- **功能**：展示本版本所有组件的版本变更情况
- **用途**：SRE 编写升级 SOP 时直接参考

- **表格列**：

| 列名 | 说明 |
|-----|------|
| 组件名称 | 组件标识，前端放第一行 |
| 当前版本 | 升级前的版本号 |
| 目标版本 | 升级后的版本号 |
| 变更 | 升级 / 不变 / 新增 / 下线 |

- **组件顺序**：
  1. 前端组件（CES-Portal）
  2. 后端组件（按名称排序）

- **导出按钮**：导出清单为 Excel/CSV 格式

## 五、版本状态定义

### 5.1 状态流转

```
draft → testing → released → upgrading → completed
开发中 → 测试中 → 研发出包 → 升级中 → 已完成
```

### 5.2 状态说明

| 数据库状态 | 页面显示 | 说明 |
|-----------|---------|------|
| draft | 开发中 | 研发正在开发 |
| testing | 测试中 | 测试正在验证 |
| released | 研发出包 | 测试通过，研发已出包，等待升级 |
| upgrading | 升级中 | 正在全网推广 |
| completed | 已完成 | 全网升级完成 |

---

## 六、交互说明

### 6.1 点击行为

| 元素 | 点击行为 |
|-----|---------|
| 返回按钮 | 返回发布计划列表 |
| 编辑按钮 | 打开编辑弹窗，可修改摘要、关联需求、关联缺陷 |
| 状态推进按钮 | 推进到下一状态 |
| 查看局点详情 | 跳转到 `/regions?version={版本号}` |
| 导出按钮 | 导出组件信息 |

### 6.2 编辑弹窗

- **可编辑字段**：
  - 版本摘要
  - 关联需求（逗号分隔）
  - 关联缺陷（逗号分隔）

- **不可编辑字段**：
  - 版本号（创建后不可修改）
  - 版本类型（创建后不可修改）
  - 版本线（由版本号自动提取）

## 七、数据来源

| 数据 | 来源 |
|-----|------|
| 版本基本信息 | Plan 表 |
| 版本线 | 从版本号提取（如 25.8.2 → 25.8） |
| 升级进度 | RegionVersion 表统计 |
| 关联需求/缺陷 | Plan.relatedRequirements / Plan.relatedBugs |
| 组件信息 | Manifest 表 + ManifestComponent 表 |

## 八、与现有设计的差异

| 原设计 | 新设计 | 原因 |
|-------|-------|------|
| 状态：草稿/待测试/待发布/已发布/已废弃 | 开发中/测试中/研发出包/升级中/已完成 | 与 PRD 统一 |
| 三列信息卡片（含创建时间） | 两列（关联需求/关联缺陷） | 创建时间无业务价值 |
| 前端版本单独展示 | 前端作为组件列入组件信息 | 统一管理，方便 SOP |
| 交付清单含「变更原因」列 | 删除「变更原因」列 | 不需要 |
| 交付清单只有「目标版本」 | 增加「当前版本」列 | 方便对比，SOP 友好 |
| 覆盖局点数量 | 改为升级进度 | 更有业务意义 |
| 状态推进按钮在头部 | 状态流程图旁边 | 逻辑更清晰 |
